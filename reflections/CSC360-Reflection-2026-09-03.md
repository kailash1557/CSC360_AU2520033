# CSC360 Reflection — 03/09/2026

This session continued from the last class and stayed practical, since a lot of it was tied to our midsem project work. We picked back up on printing ASCII trees, and talked about why this matters even in a world of real graphics. In high performance or text only computing environments, a text based tree representation is sometimes the only practical option, which is why printing one still has real use cases. Characters like slash, backslash, and vertical bar are used to represent the edges connecting nodes, and for larger trees it is generally better to lay them out horizontally rather than the usual vertical orientation, since it scales more cleanly as the tree grows.

We also covered how to build a splash screen, which is the introductory screen shown while an app or game is loading. A good splash screen usually includes the brand logo, a welcome message, and some kind of live visual element to reassure the user that the app is actually working rather than frozen. A progress bar is a common addition here too, giving the user a sense of how much longer the load will take. We also discussed that showing basic details like the app version and build information on this screen is considered good practice.

Finally we revisited testing concepts from the previous session, distinguishing unit testing from acceptance testing. Unit testing happens at the code level and is usually done by the developer to check individual pieces in detail, while acceptance testing evaluates the program as a whole from a usability standpoint and is typically done by the end user.
