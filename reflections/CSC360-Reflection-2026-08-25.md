# CSC360 Reflection — 25/08/2026

This session covered Java fundamentals and how a project is actually structured inside IntelliJ, followed by a deeper look at threads. We started by breaking down how Maven works as a build tool that reduces the manual setup needed for a project. The pom.xml file is central to this, since it tells Maven exactly where the source files are and how the whole project is organized, and even a small naming mistake in it can cause the build to fail. We also looked at how Maven tracks build stages through its lifecycle, and how running clean clears out all previously generated build files before a fresh build.

The second half of the session focused on threads. A thread is essentially the smallest unit of execution in a program, and a machine can run either a single thread or multiple threads at once depending on the task. Multiple threads become useful when one thread alone cannot efficiently handle everything happening at once. For example, in a GUI button click, one thread can handle the actual logic while a separate thread manages visual feedback like color changes or animations, so the user can see the program is responding.

This led into thread safety, which becomes a concern when multiple threads try to access the same data at the same time. Interestingly, Java Swing does not really need thread safety mechanisms since it is designed to work primarily with a single thread. We discussed why this is often preferred in practice, since keeping things like color and border consistency across a combined shape, such as merging a square and a circle, is much simpler with a single thread. Using two threads is technically possible but tends to reduce efficiency for these kinds of tasks.
